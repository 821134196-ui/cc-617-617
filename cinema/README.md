# 影院会员券 · 跨场次改签差额系统

会员改换场次、或只替同行人改一张票时，系统先算清**新旧票价与会员券优惠**，再确认**补交 / 退还差额**。
后端 Go + Gin + GORM(SQLite/WAL，纯 Go 驱动，无需 CGO)，前端 Vue 3 选座与金额对照，本地模拟支付。

## 一条命令启动

```bash
cd cinema
./run.sh                 # 默认 :8080，自动重置演示数据，预留 TTL 60s
PORT=8092 ./run.sh       # 换端口
./run.sh --no-reset      # 保留已有数据
```

启动后打开 <http://localhost:8080>。首次运行会自动下载 Go 依赖（需要网络；已固定兼容 Go 1.24 的版本）。

演示账号为会员 **张三（member_id=1）**，初始有同一订单两张《星际穿越》票（A3/A4，每张用「新人9折券」实付 ¥54）、
4 张券（可用 8 折券 / 立减 30 元券，已核销 9 折券，过期 5 折券）、4 个票价不同的场次。

## 页面流程

1. **选原票**：展示影片/场次/座位/原价/已用券/实付；同行单标注「另有 N 张票保留原场次」。
2. **选新场次与座位**：座位图区分 可选 / 他人预留中 / 已售 / 已选；可沿用原券优惠或另选可用券（已用、过期券不可选）。
3. **四栏对照**：原票 / 新票 / 券与抵扣 / 补退明细，明示 `新票应付 − 原票实付 = 补(正)/退(负)/平(0)`。
4. **确认改签**：新座位**限时预留**（倒计时）；
   - 补款：模拟支付成功 → 同一数据库事务内完成改签；
   - 退款：确认后完成改签，系统自动生成等额退款单；
   - 平价：免支付直接完成。
5. **支付结果**：成功才释放原座位并归档原票；失败/超时/取消保留原订单原座位、释放新座位、归还占用的券。
6. **回执实验室**：可重放同一回执（应判重）、先失败再发迟到的成功回执（应自动退款、绝不改签）。

## 核心业务规则

| 规则 | 实现要点 |
|---|---|
| 金额计算 | 单位「分」，`折扣券 paid=base×rate/100`；`立减券 discount=min(amount,base)`；差额=新应付−原实付 |
| 券按每张票记录 | `tickets` 行永久保存券名称/类型/折扣率/面额/抵扣额快照，改签不重算原票 |
| 已用/过期券不可再抵 | 创建改签时校验 + 条件 UPDATE 预核销（`redeemed_at IS NULL` 才成功），失败/超时归还 |
| 新座位限时预留 | `reservations` + `seat_occupancies`，后台每 2s 扫描释放，TTL 可配 |
| 并发抢座 | `seat_occupancies (session_id, seat_id)` **唯一索引**裁决 + 写事务互斥；只有一人成功，其余 409 `seat_taken` |
| 同票在途唯一 | `exchanges.active_ticket_key` 唯一索引（非终态=原票ID，终态置 NULL） |
| 支付成功才换票 | 单个事务：CAS 状态 → 建新订单/新票 → 原票置 exchanged（数据保留）→ 预留占用转新票 → **释放原座位** → 退差生成退款单 |
| 支付失败恢复 | 原票/原座位不动，新座位释放，券归还，改签单 failed，可重新发起 |
| 回执幂等 | `receipts.receipt_no` 唯一；重复到达返回 `duplicate`，不触发第二次改签 |
| 迟到成功回执 | 改签已失败/过期后收到成功收款：标记收款成功但**自动原路退款**，原票保留，绝不复活改签 |
| 同行单改一张 | 新票单独建新订单（`parent_order_id` 指向原订单），原订单其余票状态/场次/座位完全不变 |

> 退款不是改签的触发器：外部退款回执只登记退款单，绝不改变改签状态。

## 主要接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/bootstrap?member_id=1` | 票/券/场次一次性加载 |
| GET | `/api/sessions/:id/seats` | 座位图（available/held/sold/mine） |
| POST | `/api/quote` | 纯报价，不落库 |
| POST | `/api/exchanges` | 确认改签并预留新座（建议带 `idempotency_key` 防双击） |
| POST | `/api/exchanges/:no/pay` | 按差额方向：发起收款 / 确认退差 / 平价完成 |
| POST | `/api/payments/:no/mock-pay` | 模拟支付网关回执（`fail:true` 模拟失败；可指定 `receipt_no` 重放） |
| POST | `/api/receipts` | 原始回执重放入口（模拟渠道迟到/重复通知） |
| POST | `/api/admin/reset` | 重置演示数据 |

## 验证

```bash
go test ./... -count=1                 # 12 个 service 测试 + 3 个 HTTP 测试
go test ./... -race                    # 竞态检测
python3 scripts/live_verify.py         # 对真实服务打流量（先 ./run.sh 或启动 -ttl 5s）
```

测试覆盖（用户要求的验收点）：

- **并发抢座**：20 个 goroutine / 20 个 HTTP 请求同时抢同一座位，恰好 1 个成功（`-race` 通过）；
- **同行单张改签**：原票归档、新票生效、原座位支付后释放、同行票原场次不动、优惠依据完整复制；
- **补款失败恢复**：原票原座位保留、新座位释放、券归还，且可重新改签成功；
- **重复/迟到回执**：同回执号并发重放只生效一次；失败后迟到的成功回执自动退款、原票保留；
- **预留超时**：到期释放新座位、改签 expired、券归还、原票保留；之后旧支付单晚到成功仍自动退款；
- **补/退/平差额**与券规则：8 折、立减封顶、已用券/过期券拒绝抵扣。
